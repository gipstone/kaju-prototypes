Leitprinzipien

Cloud-Fähigkeit, Automation und kontinuierliche Werkzeugentwicklung werden mit harten Datenschutz-, Schreib- und Qualitätsgrenzen kombiniert.

01 · Intern

Rohdaten bleiben intern

Kunden-, Projekt-, E-Mail-, Originalplan- und geschützte Fachinformationen verbleiben in der vertrauenswürdigen KNP-Zone.

02 · Schreibgrenze

LLM schreibt nie direkt

Das lokale LLM darf lesen, analysieren und Vorschläge erzeugen. Produktive Änderungen an Projektablage oder Access erfolgen ausschließlich über freigegebene Dienste.

03 · Adaptiv

System verbessert seine Werkzeuge

Der Agent erkennt Lücken und entwickelt neue Methoden und Tools – zunächst ausschließlich experimentell.

04 · Freigabe

Produktiv nur validiert

Belastbare Ergebnisse dürfen ausschließlich auf KNP-validierten Versionen und freigegebenen Berechnungsschritten beruhen.

Selbstlernend ≠ selbstfreigebend: Das System darf aus Aufgaben lernen und neue Tools entwickeln, aber weder neue Rechenlogik noch produktive Schreibaktionen selbstständig freigeben.

Zielarchitektur

Intern gibt es zwei getrennte kontrollierte Übergänge: einen Sanitization Gateway Richtung Compute/Cloud und einen privilegierten Write Broker für echte KNP-Daten.

E-Mail-Sortierung, Projektablage und Access

Die KI darf die Ablage vorbereiten, aber nicht selbstständig produktive Projekt- oder Datenbankänderungen durchführen.

Mail UI

Eigene interne Oberfläche

Inbox mit KI-Vorschlag, Trefferwahrscheinlichkeit, vorgeschlagenem Projekt, Zielordner, Dokumenttyp und Dateiname. Ein Klick bestätigt oder korrigiert die Ablage.

Human Gate

Schreiben erst nach Bestätigung

Der Mensch bestätigt den konkreten Zielzustand. Erst danach erhält der Write Broker einen eng definierten Auftrag; das LLM besitzt selbst keine Schreibcredentials.

Write Broker

Minimal privilegierter Dienst

Darf nur freigegebene Operationen: Maildatei kopieren/verschieben, Metadaten schreiben, Access-Datensatz anlegen/ändern und Audit-Eintrag erzeugen.

Beispiel einer bestätigten Ablageaktion
transaction_id: TX-2026-0917-004182
actor: user:kai
source_message_id: <mail-id>
approved_project_id: P-0241
actions:
  - store_email:
      target: /projekte/P-0241/05_Korrespondenz/2026-09-17_mail.eml
  - store_attachments: true
  - access_link:
      project_id: P-0241
      document_type: email
      path: ...
  - write_audit_record: true

Der Write Broker akzeptiert keine freien Shell-Befehle oder LLM-Prompts, sondern nur ein festes, validiertes Aktionsschema.

Wichtige Trennung: Das lokale LLM kann einen sehr guten Ablagevorschlag machen. Der eigentliche Schreibvorgang ist jedoch klassische Software mit festen Regeln, Berechtigungen, Transaktionen und Protokollierung.

Normen, Fachbücher und Fachartikel

Lizenzierte oder urheberrechtlich geschützte Quellen werden nicht in die Cloud kopiert. Die lokale Wissensschicht beantwortet konkrete Fachfragen mit Provenienz.

Knowledge Vault

Geschützter Bestand

Originale und abgeleitete Markdown-/Bilddaten liegen ausschließlich intern und werden mit Quelle, Ausgabe, Rechten und zulässiger KI-Nutzung katalogisiert.

Research Agent

Lokale Recherche

Das lokale LLM erhält konkrete Fachfragen, recherchiert in zulässigen Quellen und liefert eine belegte Antwort.

Evidence Packet

Cloud erhält nur Fachwissen

Weitergegeben werden konkrete Aussagen, Parameter und Fundstellen – nicht die vollständigen geschützten Dokumente.

Lizenz-Gate: Ob ein Dokument automatisiert extrahiert, indexiert oder von einem lokalen LLM verarbeitet werden darf, wird pro Quelle als Rechte-Metadatum hinterlegt.

Lokale PDF-Ingestion

Capability Memory

Erfahrungen wiederverwenden

Problemklassen, geeignete Tools, Benchmarks, Fehlerbilder, Laufzeiten und Modellierungsstrategien werden strukturiert gespeichert.

Gap Detection

Fehlende Fähigkeit erkennen

Reicht kein freigegebenes Werkzeug aus, erzeugt der Agent einen Tool-Development-/Validation-Task statt still zu improvisieren.

No Auto-Promotion

Keine Selbstfreigabe

Ein vom Agenten entwickeltes Tool darf sich niemals selbst auf produktiv setzen.

Entscheidungslogik
if all_required_steps.status == KNP_VALIDATED:
    run_production_calculation()

Tool Registry, Validierung und Freigabegates

Jeder Rechenkern, jedes Skript und jeder fachlich relevante Berechnungsschritt hat Version, Status, Gültigkeitsbereich und dokumentierte Validierungsbasis.

StatusBedeutungProduktiver Nachweis
ExperimentalPrototyp oder neu entwickelte Methode.Nein
BenchmarkedAutomatische Referenzfälle bestanden, aber noch keine formale KNP-Freigabe.Nein
KNP-validiertGegen Referenzsoftware, analytische Fälle und/oder belastbare Vergleichsdaten geprüft; Version und Anwendungsbereich freigegeben.Ja
DeprecatedAlte Version; reproduzierbar archiviert und für neue Berechnungen gesperrt.Nein
Referenzsoftware

Cross-Validation

Neue Rechenkerne werden mit identischen Geometrien, Materialien und Randbedingungen gegen etablierte Software gerechnet.

Regression Suite

Freigabe bleibt reproduzierbar

Jede Änderung muss definierte Referenzfälle innerhalb expliziter Toleranzen erneut bestehen.

Human Gate

KNP gibt Version frei

Erst nach menschlicher Prüfung von Validierungsreport, Grenzen und Abweichungen wird eine konkrete Version produktiv.

Grundregel: Ein Bericht darf „validiertes Ergebnis“ nur tragen, wenn jeder ergebnisrelevante Schritt auf einer freigegebenen Version innerhalb ihres Gültigkeitsbereichs beruht.

Aktueller Soll-Workflow

Vom E-Mail-Eingang oder einer technischen Aufgabe bis zur nachvollziehbaren Ablage bzw. Berechnung.

  1. Das lokale LLM liest interne Quellen und erkennt Projektbezug, Aufgabe und erforderliche Aktion.
  2. Bei E-Mails erzeugt es ausschließlich einen Ablagevorschlag.
  3. Ein Mitarbeiter prüft Projekt, Kategorie, Dateiname und Zielordner im Human-Gate UI.
  4. Der Write Broker führt die bestätigte Datei-/Access-Änderung transaktional aus und protokolliert sie im Audit-Journal.
  5. Für Berechnungen erzeugt das Gateway ein pseudonymisiertes Compute-Ticket.
  6. Der Compute-Agent prüft Tool Registry, Capability Memory und erforderliche Evidence Packets.
  7. Nur KNP-validierte Werkzeugketten dürfen fachlich freigabefähige Ergebnisse erzeugen; andernfalls wird Entwicklung/Validierung angestoßen.
  8. Ergebnisse, Visualisierungen und Provenienz werden im internen Web-Frontend bereitgestellt.
  9. Backups, Audit-Logs und Restore-Tests sichern die produktiven Datenänderungen unabhängig vom KI-System ab.
