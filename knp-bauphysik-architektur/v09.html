1. Zwei typische Arbeitsabläufe

Die Grafik zeigt bewusst nicht nur Technik, sondern zwei konkrete Aufgaben aus dem Büroalltag.

Lesart: Workflow A bleibt komplett im KNP-Büro. Workflow B überschreitet die Grenze nur mit pseudonymisierten Technikdaten. Normen- und Wiki-Recherche wird intern ausgeführt und als schlankes Evidence Packet zurückgegeben.

2. Systemaufteilung

Technisch bleiben es nur zwei operative Welten. Hetzner übernimmt Control Plane und Compute; im Büro sitzt die vertrauenswürdige Daten-/Wissenswelt.

KNP-Büro

Trusted Zone

Datenserver/Access/E-Mail, lokales LLM, interne Task-Zuordnung, KNP-Wiki, Normen/Fachliteratur, Human Gates, deterministische Write Worker, KNP Document Factory und der ausgehende Connector.

Hetzner

Control Plane + Compute

Next.js-Web-App, API/Auth, PostgreSQL, Job Queue, Object Storage, Agent-Orchestrator, Codex/Claude Code, MCP-Rechentools, Tool Registry, Sandboxes und Reporting.

3. Kommunikation

„Empfangen“ im Büro braucht keinen offenen Port: der KNP-Connector baut selbst eine ausgehende HTTPS-Verbindung auf und holt neue Nachrichten.

KNP Connector ───── HTTPS :443 ─────► Hetzner API │ │ ├─ POST /tasks ├─ Job Queue ├─ GET /messages ├─ Research Requests ├─ POST /research-results ├─ Result Packages └─ GET /results └─ Status Long Polling / WebSocket / Polling sind möglich. Die Verbindung wird immer aus dem KNP-Netz eröffnet.
Entscheidung: Kein eigener Relay-Server und kein Site-to-Site-VPN. Die Hetzner-Anwendung stellt die minimale Broker-API bereit; Hetzner hat keine Route in das KNP-LAN.

4. MCP als Tool-Schicht

MCP standardisiert Werkzeuge innerhalb einer Zone. Zwischen KNP und Hetzner bleibt die eng definierte Connector-API.

ZoneBeispiel-ToolsZweck

8. Sicherheitsmodell

Die Hetzner-Zone wird so behandelt, als könnte ein Agent oder eine Abhängigkeit kompromittiert werden.

RegelUmsetzung
Keine Route nach KNPKein VPN/SMB/SSH/DB-Zugang; kein interner DNS; kein KNP-Credential auf Hetzner.
Nur definierte AustauschobjekteSchema-validierte Task-, Research-, Evidence-, Result- und Status-Pakete.
Rückgaben sind untrustedKeine Shell-/SQL-/Access-Anweisungen aus Cloud-Paketen ausführen; Dateien/HTML/Freitext werden validiert/sanitisiert.
Produktives SchreibenNur feste interne Worker nach Human Gate; keine freien LLM-Serverrechte.
Agent-IsolationPro Ticket separater Workspace/Container; nur explizit freigegebene Dateien und Tools.
